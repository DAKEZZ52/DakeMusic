# NetEase 风格 UI 改造方案（只改界面，不改行为）

> 目标版本：2.4.6 · 编写时间：2026-11-03 · 基于 `main` 分支 `5315048`
> 边界：**只改模板类名、CSS 与设计令牌**；不碰 `script`、事件、路由、播放/网络逻辑。

---

## 1. 目标

把界面的视觉语言向网易云音乐靠拢（布局骨架、配色关系、圆角与阴影的轻重、信息密度），但：

- 不复制网易云的 logo、图标资源、字体文件
- 不改变任何交互行为（点击、拖拽、播放、同步）
- 保持深色主题可用（两套主题同步改）

---

## 2. 现状盘点

| 项目 | 现状 | 影响 |
|---|---|---|
| 设计令牌 | `style.css` 中 10 组、约 120 个变量（`:root` 5–148，`.dark` 150–196） | 改令牌可覆盖大部分观感 |
| 动态主题色 | `utils/color.ts:332–337` 从封面取色，运行时写 `--color-primary*` 等 5 个变量 | 主色会随歌曲变化，**本方案暂时不动** |
| 硬编码圆角 | `rounded-[Npx]` 共 **43 处** | 统一圆角需要逐个改，无法只靠令牌 |
| 外壳代码 | `Sidebar.vue` 1844 行、`TitleBar.vue` 1317 行、`PlayerBar.vue` 902 行 | 结构改动风险集中区 |
| 页面代码 | `views/` 89 文件 49,589 行、`components/` 107 文件 29,308 行 | 全站改造需要排期 |

## 3. 视觉规格（目标 vs 现状）

### 3.1 颜色

| 令牌 | 现状 | 目标（网易云感） | 说明 |
|---|---|---|---|
| `--surface-main-base` | `#f5f5f7` | `#f5f5f7` | 基本一致，保留 |
| `--surface-sidebar-base` | `#ffffff` | `#ffffff` | 一致；但去掉磨砂改为纯色 |
| `--text-main` | `#1d1d1f` | `#333333` | 稍柔和 |
| `--text-secondary` | `#4b5563` | `#666666` | 一致方向 |
| `--border-light` | `#e5e5ea` | `#e5e5e5` | 中性灰 |
| `--color-brand` | `#0071e3` | **暂不动** | 等主色方案确认后再定 |
| `--color-primary*` | 运行时由封面决定 | **暂不动** | 保留动态取色能力 |

### 3.2 圆角

| 元素 | 现状 | 目标 |
|---|---|---|
| 卡片/封面 | 12–20px | **4–6px** |
| 按钮/输入框 | 12–14px | **4px** |
| 弹窗 | 16–20px | **8px** |
| 头像/胶囊 | 50% / 999px | 保留（网易云也用圆形头像） |

落地方式：先改 `@theme` 与常用类，再逐页清理 43 处 `rounded-[Npx]`。

### 3.3 阴影

| 令牌 | 现状 | 目标 |
|---|---|---|
| `--shadow-card` | `0 8px 18px rgba(15,23,42,.08)` | `0 2px 8px rgba(0,0,0,.06)`（几乎无感） |
| `--shadow-card-hover` | 带主色光晕 | 去掉光晕，仅加深 1 级 |
| `--shadow-elevated` | 12/32px | `0 4px 16px rgba(0,0,0,.10)` |

### 3.4 布局骨架

| 区域 | 网易云做法 | 现在的做法 | 改造要点 |
|---|---|---|---|
| 侧栏 | 纯白、无磨砂、选中项灰底 + 左侧红条 | 半透明磨砂、圆角选中块 | 去磨砂、选中样式改左条 |
| 标题栏 | 与内容同底色，无浮起 | 与侧栏同色带模糊 | 去模糊、降低对比 |
| 播放栏 | 贴底一条、上边框 1px、无圆角 | 浮起卡片、12px 圆角、投影 | 去掉圆角与投影，改贴底 |
| 内容区 | 顶部有分区标题与筛选行 | 已有类似结构 | 微调间距与字号 |

## 4. 实施计划（三步，逐步验收）

### 第 1 步：全局令牌层（风险低）

- 改：`style.css` 的 `:root` / `.dark` 的**颜色、圆角、阴影**令牌
- 不改：任何 `.vue` 模板与布局
- 预期效果：全站底色、文字、卡片轻重、圆角整体变化；布局不动
- 验收：截 4 张图（首页、详情页、设置页、深色模式）对比
- 回滚：单次提交，`git revert` 即可

### 第 2 步：外壳对齐（风险中）

- 侧栏：去磨砂、选中项左红条、分组间距压缩
- 标题栏：去模糊、搜索框与按钮对齐方式整理（**不碰**那层 Popover 包裹与容量算法）
- 播放栏：去圆角投影、改贴底、进度条颜色跟随 `--color-primary`
- 验收：每改一处截图确认，连续 3 个区域分别提交

### 第 3 步：内容层（风险中，量大）

- 卡片：统一 4~6px 圆角、去掉悬浮光晕
- 列表行：行高与字号对齐网易云（约 32px 行高、13px 正文）
- 逐页推进：首页 → 详情页 → 搜索 → 设置

## 5. 已知风险与对策

| 风险 | 表现 | 对策 |
|---|---|---|
| 标题栏 Popover 包裹层 | 改搜索框宽度会导致点击被遮挡 | 不动结构，只改颜色/边框 |
| 标题栏容量算法 | 按钮数量随窗口变化被挤进「…」 | 不改 `updateToolbarCapacity` |
| 侧栏嵌套滚动 | 改高度会压掉歌单 | 保持 `sidebar-body-scroll` 单层滚动 |
| 43 处硬编码圆角 | 令牌改了但局部仍是旧圆角 | 第 3 步统一清理，逐文件提交 |
| 深色模式 | 只改浅色会导致深色错位 | 每次同时改 `.dark` 对应令牌 |
| 动态主题色 | 主色被封面覆盖，改了看不出来 | 本方案不动主色 |

---

## 6. 明确不做的事

- 不改任何 `script` 逻辑、事件绑定、路由、状态管理
- 不引入新的 UI 框架或图标库
- 不复制网易云的品牌资源
- 不做无验收依据的批量替换（每次改动必须能截图对比）

---

## 7. 每次改动的固定流程

1. 只改一个区域（例如"侧栏选中项"）
2. 启动应用截图（`PrintWindow` 抓窗口，避免被其他窗口遮挡）
3. 与改前对比，确认无布局塌陷
4. 单次提交，提交信息写明改了哪个区域
5. 推送到 GitHub
